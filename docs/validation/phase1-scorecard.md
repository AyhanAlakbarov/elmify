## What this document does and does not prove

**Proven:** the acceptance-gate *machinery* — `Phase1Scorecard`, `passes()`,
`scripts/evaluate_phase1.py`, and `tests/acceptance/` — is implemented,
exercises the correct precision/recall/support/lift arithmetic, correctly
reports RED when evidence is missing (Task 18 Step 2), and correctly
recomputes every named gate against real regression tests where those gates
depend on already-implemented, already-tested product behavior (approval
linkage, `MessageGroupId`, quiet-tenant threshold, controlled egress,
unknown-host denial, branding/roles, audit dossier, paid report, last-
reviewed-result preservation).

**Not proven — and not claimed:** that Phase 1 has passed real
recommendation-quality acceptance. The precision/recall/official-claim-
support/unsupported-claims/verified-funded-lift numbers above are computed
from hand-written SYNTHETIC placeholder fixtures under `tests/benchmarks/`
(every file marked `"_synthetic": true`; see `tests/benchmarks/README.md`).
They prove the pipeline's arithmetic is wired correctly end to end. They are
not, and must never be read as, the required independent-researcher blinded
reference lists or the consultant-reviewed diverse-profile labels. Because
of this, `scripts/evaluate_phase1.py` exits `2` (not `0`) even when every
individual number clears its threshold on this data, and the "Overall gate
status" line above is qualified accordingly whenever synthetic data is in
use.

A separate gap was found while building this machinery and has since been
closed: **mandatory MFA for platform admins, agency owners, and counselors**
(Section 3.4) is now enforced via `apps.tenancy.middleware.require_staff_mfa()`
and proven by `tests/tenancy/test_mfa.py`. This closes the P1-mfa blocker
mechanism-wise; it does not by itself prove real Phase 1 acceptance, which
still requires the real benchmark data described above.

A read-only security review of Tasks 13-18 (counselor review/audit, paid
report, white-label concierge, document quarantine/export/deletion,
deployment, acceptance gates) ran on 2026-08-16 and fixed nine findings,
including the MFA gap noted above, a cross-tenant object-key vector in
document quarantine, an untrusted `tenant_id` that could override verified
tenant context, and a payment double-credit race. Full writeup and commit
list: `docs/security/2026-08-16-tasks-13-18-review.md`. All nine fixes are on
`master`; the pre-existing `test_task7_rls_policy_shapes_and_runtime_acl`
failure referenced in earlier versions of this document (a stale Task 7
assertion that never accounted for Task 9's `catalog_ingestion_write`
policy) is also fixed and no longer excluded from the P1-12 row below.
