# A search provider whose terms permit storage — synthesis across two runs

**Adjudicated 2026-08-30** against `2026-08-30-live-search-prerun-recon.md`, which was written before
either run and handed to neither. Runs: `2026-08-30-live-search-review-1.md` (A) and
`-review-2.md` (B).

**The runs are not of comparable quality, and the adjudication says so early because it changes how
the rest reads.** Run A is well-sourced, dates its quotes, distinguishes silence from permission, and
finds three material facts neither the control nor run B reached. Run B reaches its central
recommendation through a clause it did not find, a fabricated interpolation inside a verbatim quote,
and a product that has been closed to new customers for months. Where they conflict, the default is
run A, and every instance below was re-verified against the primary document rather than settled by
preference.

---

## 1. The answer is yes, and it is Tavily — by structure, not by silence

**Question 0 has an affirmative answer, and it is stronger than either run stated.** The control
recorded Tavily as *silent*. That was too weak. The chain, re-read from `tavily.com/terms` (last
updated 4 May 2026) on 2026-08-30:

1. §1.7: **"'Services' means the Tavily online search engine… and any associated application
   programming interface(s)"**.
2. The definition of Output: **"'Output' means the outputs or results delivered or made available to
   Customer through the Services… including the generated text, information, links or other materials
   included therein."** A URL is expressly Output — "links" is in the enumeration.
3. **"For clarity, the term 'Services' does not include Output."**
4. §3.2's seventeen restriction limbs attach, every one of them, to **the Services**. Not one reaches
   Output.
5. The only Output-facing restriction is §6.4(i): "use Output generated by the AI Functionality to
   develop **models** that compete with the Company". A funding catalogue is not a competing model.

So retention of a URL is not permitted by an absent clause — it is permitted because the document
**defines the restricted object to exclude the thing we keep**. That is a positive structural finding
and it is the single most valuable output of this run. Run A found steps 3 and 4 and drew the right
conclusion; the control had marked this silence; run B disqualified Tavily outright.

**Two real limits on it, neither fatal:**

- **Tavily is partly a reseller and says so:** "Tavily may share Customer Input with its affiliates and
  vendors and generally as needed to provide the Services (**including making queries on third-party
  public web indexes**)". Sourcing rule 3 says a reseller inherits its upstream's terms. Which upstream
  is undisclosed. **But the inheritance problem is Tavily's, not ours**: we contract with Tavily, not
  with its supplier. If Tavily lacks the rights it grants, that is a breach between Tavily and its
  upstream, and our exposure is *service continuity*, not our own breach. This is the material
  difference from SerpApi, whose terms explicitly push use-side liability back to us.
- **§3.2(xvi)**, which neither run found: Customer shall not "use the Services or the Output to make
  **automated decisions without human oversight** that have a significant adverse impact on individual
  rights in high-risk areas such as employment, healthcare, finance, legal, housing, insurance or
  social benefits." Education is not enumerated, which is the one leg this rests on; whether it
  carries the clause alone is an open legal question.

  **Correction, 2026-09-08.** This paragraph originally added "and funding advice is
  counselor-reviewed by design". That was not true of the product it described: `phased
  requirements.md` §38 ships the recommendation pool and pack to the student un-gated by counselor
  review, on purpose. Oversight lives downstream instead — document approval, and the six escalation
  triggers during application execution. The finding about §3.2(xvi) stands; the second leg of the
  argument for satisfying it does not, and should not be relied on.

## 2. Mojeek: run A found the grant, and both runs missed what backs it

Run A quotes the FAQ correctly — "You can store results on Business plan and optionally on the
Enterprise plan" — and adds a genuinely useful second grant the control missed: "You can use the data
with other data sources for research, reporting, AI or whatever you wish." It then ranks Mojeek **first**
on the strength of an "explicit written storage grant".

**That is the Brave trap in reverse, and this programme has already paid for the lesson.** On
2026-08-28 a Brave marketing FAQ promised storage and the binding ToS forbade it; the finding was
corrected and the verdict demoted. Here a marketing FAQ grants storage and — per the control, §3 —
`mojeek.com/about/terms.html` is website terms that say nothing about API output, and no API contract
is published anywhere on the site. Every plan row ends in "Contact".

Neither run asked what document grants the right. Run A over-trusted it; **run B got Mojeek
affirmatively wrong**, recording "Terms completely silent on retention" and citing the XML
response-format documentation page — it never found the pricing page at all.

**Verdict: Mojeek is a strong lead and not a cleared provider.** The same standard that demoted Brave
applies. It is also the provider both runs independently rate weakest on non-English coverage, which
matters for a query set spanning Turkish, Korean, Chinese and Hungarian.

## 3. Google is disqualified twice over, and run B's Rank 1 rests on both errors

Run B's central recommendation is **Google Custom Search JSON API, because it is "entirely silent on
the persistent caching or storage of bare URLs."** Both halves fail.

**First, the clause exists.** `developers.google.com/terms`, §e "Prohibitions on Content", read
2026-08-30 and quoted in the control and by run A: "Scrape, **build databases**, or otherwise create
permanent copies of such content, or keep cached copies longer than permitted by the cache header."
Run B cites that exact URL and quotes a different, irrelevant passage about sublicensing and ITAR
data. The silence it relies on is an artefact of not finding the section.

**Second — and this ends it — the product is closed.** Verified independently at
`developers.google.com/custom-search/v1/overview` on 2026-08-30:

> **"Note: The Custom Search JSON API is closed to new customers."**

with the same page recording service discontinuation on **1 January 2027**. Run A caught this and run B
did not. Run B's top recommendation is a product we could not sign up for and that shuts down in
sixteen months.

## 4. Two sourcing failures, and only one of them is honest

**Run B fabricated an interpolation inside a verbatim quote, and disqualified a provider on it.** It
renders Tavily §6.4(i) as:

> "…to develop models **(which would include competing databases or search systems)** that compete with
> the Company…"

The parenthetical does not appear in the document. The actual clause reads "use Output generated by the
AI Functionality to develop models that compete with the Company and/or any of the Company's AI
Functionalities." Run B's own gloss, placed inside quotation marks and treated as operative text, is
what carries Tavily from permitted to "extreme legal hazard" and into its disqualified tier. A
paraphrase presented as a quote is worse than a wrong summary, because it defeats the check the
sourcing rules exist to enable.

**Run B's citation list is the underlying cause.** Its sources for terms claims include an Apple App
Store listing (for You.com's terms), a GitHub repository of MCP servers (twice, as the source for
Marginalia's terms), a scraping vendor's blog, a Y Combinator comment, and a personal SEO blog. The
prompt's sourcing rule 5 forbids exactly this. Its two largest errors — Google and Mojeek — both trace
to not opening the provider's own operative page.

**Run A's failure is different in kind and worth stating plainly:** it over-reads a marketing FAQ as a
"written storage grant" (§2 above). That is a misjudgement of evidentiary weight, not a fabrication,
and it is visible because run A quoted its source accurately enough to be checked.

## 6. Where the runs contradict each other, and which is usable

**Common Crawl for university subdomains — the sharpest conflict, and it decides an architecture.**

- Run B: the CDX index is "arguably the most powerful tool for this specific subdomain mapping task"
  and "returns every single URL across every subdomain observed". Sourced to a scraping-tool blog.
- Run A: Common Crawl "samples rather than deep-crawls", quoting Common Crawl's own words — **"we do
  not aim to have a complete copy of any web site"** — so "a rarely-linked funded-school subdomain is
  exactly what it is most likely to miss."

**Run A is the usable one**, and not merely because it is better sourced: run B's own text concedes the
freshness problem (monthly snapshots) and that CDX cannot be queried by content, then recommends
downloading and locally indexing whole university domains — an architecture it costs at nothing. Run
B's Rank 3 is a proposal to build a search engine in order to avoid licensing one.

Both runs agree, correctly, that self-hosted search cannot discover unseen URLs, and that sitemaps miss
precisely the separately-administered graduate-school subdomains that motivated wanting search.

## 7. What this changes

1. **The live-search `LeadSource` is unblocked.** It was blocked on the belief that no provider permits
   retention. Tavily's structure permits it, and the design constraint the last session derived —
   persist the URL, never the result object — makes the permission comfortable rather than marginal.
2. **The provider decision is Tavily first, on terms.** Mojeek second and conditional on obtaining the
   contract behind its FAQ *and* passing a non-English recall test, which both runs expect it to fail.
   Brave requires a paid storage tier and its definitions bring a bare URL inside "Search Results"
   regardless. Exa, Serper and SerpApi are Google-derived or restrictive. Google, Bing, DuckDuckGo and
   Startpage are not options at all.
3. **`CLAUDE.md` gains the retention rule**, in the web-fetching section: the engine consumes a URL and
   discards the response; no result object, snippet column, or SERP cache is ever persisted. The failure
   mode is someone adding a cache table for performance in a later sprint, and it would move us from
   comfortably inside Tavily's terms to relying on an argument.
4. **Record §3.2(xvi)** — no automated high-risk decisions without human oversight — next to that rule,
   because it constrains a feature nobody has proposed yet.
5. **The 2026-08-28 recommendation to ask Brave about transient storage is withdrawn.** Brave's own
   definitions answer it, and the provider we would ask is no longer the front-runner.

## 8. Still open

1. **Which upstream index Tavily queries.** The one question worth putting to a provider in writing.
   It does not change our contractual position (§1) but it decides whether Tavily's supply is durable.

   **And sourcing rule 3 does not run downstream.** "A reseller inherits the upstream's terms" directs
   a *researcher* to follow the chain up and establish what a reseller can truthfully offer. It does
   not push the upstream's restrictions onto the end customer, who is not party to that agreement. The
   rule bites hard against SerpApi, whose terms disclaim use-side liability and hand the exposure back
   to us, and does nothing against a provider that grants without carve-out. Applied downstream it
   dresses an ordinary vendor-continuity question up as a legal one, which is what happened on the
   first reading of this run.
2. **Mojeek's binding API contract** — whether one exists, and whether it matches the FAQ. Cheap to ask;
   they already sell the right.
3. **Non-English recall, untested by anyone.** Both runs *assert* coverage rankings for German, Korean,
   Turkish, Chinese, French and Hungarian; neither issued a query. Check 11 has now gone unmet in three
   consecutive rounds of this programme. The test is ~50 known funded-school pages across the six
   languages against two providers, and it is a day's work that would settle a question no amount of
   further reading will.
4. **Run A's *Google v. SerpApi* claim** — a dismissal granted 20 July 2026, sourced to SerpApi's own
   release, i.e. a party to the litigation. Unverified here and not decisive: SerpApi is out on upstream
   terms either way.
5. **Exa's current wording.** Both runs disagree about it (run A: §4.2(a) bars retention; run B: "terms
   are completely silent"), and neither the control nor this adjudication re-read it. Run A's version
   matches the 2026-08-28 probe, which read the document end to end, so it is the presumptive one.
   Immaterial: Exa is not a candidate.
