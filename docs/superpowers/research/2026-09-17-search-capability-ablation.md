# Which search capability actually helps, and which country property decides it

Measured 2026-09-17. Two experiments: a one-flag-at-a-time ablation on Germany scored against a
377-funder answer key, then the same flags across **four structurally different countries** scored
on *locally-based funders found* — so the conclusions are properties of the method, not of Germany.
1,529 domains classified once by `OPENAI_EXTRACTION_MODEL` for funder status and organisation
country. Throwaway probes; nothing persisted into the product.

## 1. Germany, with ground truth — recall against 377 known funders

Three fixed queries per config, one parameter changed at a time.

| config | recall | Δ vs its baseline |
|---|---|---|
| **Brave, 10 result pages** | **18.0%** | **+6.1 pts** |
| Brave, 10 pages + `search_lang=de` | 17.8% | −0.2 |
| Brave, `country=ALL`, 10 pages | 15.1% | −2.9 |
| **Exa, `numResults=100`** | **14.9%** | **+8.8 pts** |
| Brave, 3 pages (the sweep's setting) | 11.9% | — |
| Exa, baseline 25 results | 6.1% | — |
| Firecrawl, `categories:["pdf"]` | 6.1% | +1.3 |
| Exa, `includeText:["Stipendium"]` | 5.3% | −0.8 |
| Tavily, baseline | 5.0% | — |
| **Tavily, `language:"de"`** | **4.0%** | **−1.0** |
| **Exa, `category:"company"`** | **3.4%** | **−2.7** |
| **Tavily, `language` + `filter_by_language`** | **2.7%** | **−2.3** |
| Exa, `category:"publication"` | 0.5% | −5.6 |

**Two capabilities this repo had recorded as the obvious wins are losses.** `2026-09-17-cell-saturation-measurement.md`
named Tavily's `language` parameter and Exa's `category:"company"` as the biggest unused levers.
Measured, the language filter *narrows* rather than re-ranks — adding `filter_by_language` nearly
halved recall — and `category:"company"` costs 2.7 points because its entity pipeline is tuned to
businesses and misses foundations. Both corrections belong in the design.

**No single configuration exceeds 18%.** The 377-funder key was itself built from 99 queries, so
coverage comes from query volume × depth, never from one well-configured call.

## 3. Five rules, each with the country property that parameterises it

**Rule 1 — Depth is the primary lever, and its return is proportional to the country's index depth.**
Brave 3→10 pages: DE +47%, TR +68%, AZ +27%, ID +104%. Exa 25→100: DE ×3.4, TR ×2.0, AZ ×1.7,
ID ×2.2. Depth pays everywhere and pays *least* where the index is thinnest, because there is no
hundredth Azerbaijani funder page to rank. Run to the provider maximum; expect the gain to track a
measurable prior — the country's ROR, Wikidata and Diffbot nonprofit counts.

**Rule 2 — Write the query in the local language; never ask the provider to filter by language.**
Local-language queries beat English on locally-based funders in **all four** countries: union of
local vs English gave DE 110/62, TR 80/54, AZ 22/14, ID 84/50. The starkest single case is Exa in
Germany — **84 local funders from German queries against 16 from English, a 5× gap**. But English
still contributes a unique tail (35, 27, 5, 17), so both passes run, local first.
**This refutes `2026-08-30-search-recall-measurement.md`**, which concluded local-language queries
were "a strict subset of English on every provider". That held for re-finding 16 known root pages
under `include_domains`; it does not hold for open-web discovery of local organisations.

**Rule 3 — Never set the provider's `country` filter.** Brave with vs without: DE +0, TR −1, AZ +0
(no enum exists), ID **−8**. Inert at best, and in Indonesia it destroyed eight local funders.

**Rule 4 — Brave's `search_lang` is measurably inert.** Jaccard of the domain sets with and without
it: 1.000, 0.985, 1.000, 1.000. A documented parameter with no observable effect on results.
Tavily's `language` is worse than inert — harmful in three of four countries (−3, +1, −2, −7).

**Rule 5 — Recall generalises; precision does not, and precision sets the reading budget.** Share
of returned domains that are a funder based in the country:

| | Exa 100, local | Brave 10 pages, local |
|---|---|---|
| Germany | **61%** | 57% |
| Türkiye | 40% | 39% |
| Indonesia | 26% | 46% |
| **Azerbaijan** | **10%** | 17% |

Azerbaijan costs five to six times as much reading per funder found as Germany. And English queries
there are actively misleading: Brave returned 37 funders of which only **6** were Azerbaijani — the
other 31 were foreign or global bodies that merely rank for Azerbaijani scholarship terms. So the
§4.7 classifier is not an optimisation in a thin-index country, it is what stops 85% of the reading
budget being wasted.

## 4. The answer to "will this work for every country"

**No — and the property that predicts failure is measurable before any query is spent.** Azerbaijan
yielded 22 local funders across six configurations and three queries, and depth bought only ×1.7.
That is not a query problem; the Azerbaijani web does not contain a hundred ranked funder pages.
Where the index is thin, more querying cannot help, and the spine has to change: the national
register, hub pages (ministry and agency announcement pages), hand-curation, and Diffbot's entity
graph — which held 2,596 Azerbaijani nonprofits, far more than search surfaced.

So the sweep is the right spine **where the index is deep**, and index depth is a per-country prior
we already hold for 46 countries. That prior, not a per-country hand-tune, is what selects the route.

## 5. Limits

One run per configuration, no variance estimate. Three queries per country per config — the German
plateau measurement used 99, so these are sensitivity readings, not recall figures. Classification is
a single unaudited model pass; the German answer key is itself model-classified, so Rule 1's absolute
recall percentages inherit its error, though the *comparisons* between configs do not. Firecrawl
returned HTTP 429 at `limit=50` on the free tier and was dropped from the cross-country run. And no
funder here has been read: a funder found is still not an award served.

## 6. The regional-engine hypothesis, tested and refuted (2026-09-17)

§4 proposed a regional index — Yandex for the Caucasus and Central Asia — as the fix for
Azerbaijan's 10–17% precision. SerpApi proxies Yandex, Google, Baidu, Naver, Bing, DuckDuckGo and
Yahoo behind one key, so the hypothesis was cheap to test on the case it was invented for: the same
three Azerbaijani-language queries, scored on funders based in Azerbaijan, against the 28 the four
existing engines had found.

| engine (via SerpApi) | domains | funders | Azerbaijani funders | **new vs baseline** |
|---|---|---|---|---|
| Yandex (`lang=az`) | 30 | 4 | 4 | **0** |
| Google (`gl=az&hl=az`) | 22 | 5 | 5 | **1** (`gdu.edu.az`) |
| Bing | — | — | — | HTTP 400 |
| DuckDuckGo | — | — | — | HTTP 400 |

**Yandex added nothing.** Zero Azerbaijani funders the four-engine baseline had not already found,
and Google added one. The hypothesis conflated *a deeper regional index* with *more of the thing we
are looking for*. Yandex's advantage is Russian-language depth; it does not create Azerbaijani
scholarship pages that do not exist. This is the same conclusion §4 reached from the other
direction — Azerbaijan's constraint is the world, not the query, and not the index either.

**So the honest answer to "is there a Yandex for South Asia or Latin America": no, and it would not
help.** Regional engines with genuinely independent indexes exist in few places — Yandex
(Russia, Caucasus, Central Asia), Baidu (China), Naver (Korea), Seznam (Czechia), Coc Coc (Vietnam).
Across South Asia and Latin America, Google holds roughly 95–98% share and there is no
domestic engine of scale, so Google *is* the local index. And the Azerbaijani test says the marginal
engine is worth ~0–1 organisations where the underlying web is small.

**The predictor is web size, not development level, and that refines §4's rule.** Indonesia returned
**55** local funders on Brave and 50 on Exa at 26–46% precision — not a thin index at all — and
India carries 17,254 higher-education institutions in Wikidata and 2,106 in ROR. The thin-index
route (registers, hub pages, hand-curation, Diffbot's graph) is for **small-web countries** —
Azerbaijan, Georgia, Armenia, Kyrgyzstan, Turkmenistan and their peers — not for large developing
markets, which the global engines index adequately.

**What SerpApi is for, unchanged by this.** The terms position of `2026-09-17-diffbot-perplexity-recon.md`
stands: its shield covers collection and explicitly not use, and it cannot grant rights to indexes
it resells, so **no host may enter the catalog because SerpApi pointed at it**. Its legitimate role
is the transient yardstick — run it beside a sweep, count what the clean engines missed, discard the
list. This measurement is exactly that role, and its finding is that the gap it measured is
approximately zero. Free plan: 250 searches a month.

## 7. Baidu and Naver, tested — a regional engine pays when the web is large but out of reach

§6 refuted the regional-engine idea on Azerbaijan, where the web is small. China and Korea are the
opposite case: large national webs that the global indexes reach imperfectly — China because Google
is blocked there, Korea because much of the content sits on Naver-hosted platforms. Tested the same
way: three local-language queries, scored on funders based in that country, against a global
baseline of Brave at 10 pages plus Exa at 100 results.

**China** — global baseline: 249 domains, **130 Chinese funders**.

| engine | domains | funders | in-country | precision | **new vs global** |
|---|---|---|---|---|---|
| Brave 10p | 138 | 97 | 81 | 59% | 0 |
| Exa 100 | 157 | 113 | 90 | 57% | 0 |
| **Baidu** (SerpApi) | 21 | 16 | **16** | **76%** | **7** |
| Google (SerpApi) | 23 | 17 | 16 | 70% | 2 |

Baidu's 7: `xjtu.edu.cn`, `xidian.edu.cn`, `ynu.edu.cn`, `tjut.edu.cn`, `ahmu.edu.cn`,
`bttc.edu.cn`, `xmoc.edu.cn` — all Chinese institutions, from **three searches**, at the **highest
precision measured anywhere in this exercise**. Baidu's index *is* the Chinese web, so nearly
everything it returns is a Chinese institution.

**Korea** — global baseline: 212 domains, **69 Korean funders**.

| engine | domains | funders | in-country | precision | **new vs global** |
|---|---|---|---|---|---|
| Brave 10p | 106 | 55 | 50 | 47% | 0 |
| Exa 100 | 148 | 44 | 40 | 27% | 0 |
| **Naver** (SerpApi) | 22 | 11 | **11** | 50% | **5** |
| Google (SerpApi) | 22 | 11 | 11 | 50% | 1 |

Naver's 5 include two genuine Korean foundations — `daesangfoundation.or.kr`,
`seoulfuture.or.kr` — plus `khu.ac.kr`, `yu.ac.kr`, `sjs.ac.kr`.

**The rule, now in three parts.** A regional engine pays where the national web is **large** *and*
**partly outside the global indexes' reach**: separated by policy (China) or concentrated on
national platforms (Korea). It pays **nothing** where the web is simply small (Azerbaijan: Yandex
added 0). And where the web is large and openly indexed, the global engines already have it —
Brave and Exa found 130 Chinese and 69 Korean funders on local-language queries, and Google via
SerpApi added only 2 and 1 respectively.

**Verdicts on the four proposed.**

| engine | verdict | reason |
|---|---|---|
| **Baidu** | **adopt** | +7 institutions from 3 searches at 76% precision; China is a destination with a major state scheme (CSC) |
| **Naver** | **adopt, smaller** | +5 including two foundations; Korea has GKS and a large university sector |
| Seznam (Czechia) | **skip** | 10M-person web, EHEA, DEQAR holds 83 — the Azerbaijan case, predicted ~0 |
| Coc Coc (Vietnam) | **skip** | ~5–10% share, partly proxies Google, no SerpApi engine, and Vietnam is an origin market in this plan rather than a destination |

**The catch is terms, not capability.** Both were reached through SerpApi, whose shield covers
collection and explicitly not use and which cannot grant rights to indexes it resells — so feeding
the catalog from them inherits the §2 problem in `2026-09-17-diffbot-perplexity-recon.md`.
**Naver publishes its own developer API**, which would be a direct contract to read and is the
route to prefer. **Baidu offers no comparable public search API**, so Baidu is reachable only
through a reseller, which makes its adoption an owner decision on the terms position rather than an
engineering one.

## 8. Vietnam, and a framing error corrected (2026-09-17)

§7 skipped Coc Coc partly because "Vietnam is an origin market in this plan rather than a
destination". **That reasoning was wrong twice over.** The owner's objection: if Vietnam offers
funding to international students, Indian, Pakistani and African students want it. Correct — and a
country is a destination for *some student*, never by classification. The origin/destination split
belongs to a demand cell, not to a country, and §5's corridor list is a priority ordering, not a
taxonomy.

Tested with Vietnamese-language queries for funding available to international students in Vietnam:

| engine | domains | funders | **Vietnamese funders** | precision |
|---|---|---|---|---|
| Brave 10 pages | 89 | 26 | 22 | 25% |
| Exa 100 | 159 | 65 | **61** | 38% |
| Google (SerpApi) | 19 | 12 | 11 | 58% — **+1** over the global pair |

**Global baseline: 70 Vietnamese funders.** And they are real inbound providers —
`fulbright.edu.vn`, `buv.edu.vn` (British University Vietnam), `cfvg.org`, `bkfund.vn`,
`dav.edu.vn`, plus a long tail of universities (`hcmut.edu.vn`, `ftu.edu.vn`, `ctu.edu.vn`,
`haui.edu.vn`…). So the owner's premise holds: Vietnam has inbound master's funding worth surfacing.

**But the conclusion on Coc Coc is unchanged, now for a measured reason rather than a framing one.**
Vietnam behaves like Indonesia — a large, openly indexed web where the global engines already hold
the material, and Google via SerpApi added exactly one funder. That is the third leg of §7's rule:
large and open ⇒ no regional engine needed. Coc Coc stays out because it would add ~0–2, not because
Vietnam does not matter.

## 9. Owner decision, 2026-09-17 — SerpApi for Baidu and Naver

Adopted: Baidu and Naver are used through SerpApi rather than waiting on direct contracts. The
owner's reasoning is that we do not train a competing search model, which is the condition Exa and
Brave attached in writing.

**One factual matter that reasoning does not reach, recorded so the decision is made on the real
text.** SerpApi's protection is not about training. §13 assigns liability for *"the lawful
collection of public search data (scraping, parsing, and related actions), but not for how that
data is ultimately used"* — and it applies **"for all recurring plans except the Free, Starter, and
Developer plans."** We are on the Free plan, so today there is no shield at all; a recurring paid
plan is what activates it. Separately, SerpApi cannot grant rights to indexes it resells, so
Baidu's and Naver's own positions are not waived by SerpApi's — though we hold no contract with
either, which is the ground the decision stands on.

The engineering discipline is unchanged and independent of all of it: only a URL is read from any
provider response, the origin is fetched and verified, and nothing from a provider object is ever
persisted (§4.6 of the design). Under that discipline the stored artefact is what the institution's
own server returned.
