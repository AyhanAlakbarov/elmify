Read-only application-code review of commits `7406904..75e756e` — counselor
review/audit (Task 13), the paid consultation report (Task 14), white-label
concierge roles (Task 15), document quarantine/export/deletion (Task 16),

## Findings and fixes

All nine were fixed on `master`, one commit each, every fix's test verified
to fail without the fix (reverted, confirmed red, restored).

| # | Finding | Fix | Commit |

| 2 | `apps/concierge/documents.py:register()` stored a caller-supplied object key verbatim (docstring conceded the validating view was "not implemented here"), so nothing stopped a key naming another tenant's prefix — which `open_document()` would then read. | Key is now derived from `tenant_id` + a freshly minted `document_id`; the parameter is gone, so a cross-tenant key is unconstructable rather than merely rejected. | `8fe7657` |

## Explicitly not changed

- **Tasks 14/16 have no HTTP surface.** Nothing calls `generate_report`,
  `open_document`, `build_export`, `build_dossier`, or `advance_deletion`
  except tests. Wiring them up is a feature, not a security fix, and is
  exactly where findings #2, #3, and #7's IAM gap become live — fix the
  caller with those constraints in hand, not after.
- **IAM was not widened.** `WebTaskRole` deliberately lacks `s3:PutObject`;
  the tempting "fix" for #7's AccessDenied is a bucket-wide grant. Don't.
